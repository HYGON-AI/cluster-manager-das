# 能力与验证边界

本文记录当前 `0.4.2` 源码中已识别且尚未全部整改的使用限制，供训练前验收和维护者评审使用。它不是新的整改任务单，也不替代既有问题清单；更新说明不会修复代码或关闭历史问题。命令与结果目录见 [USER_GUIDE](USER_GUIDE.md)，操作语义和协议见 [DESIGN](DESIGN.md)，实现位置见 [PROJECT_STRUCTURE](PROJECT_STRUCTURE.md)。

## 当前使用限制

| 范围 | 当前限制及影响 | 使用与验收要求 |
|---|---|---|
| 环境与身份预检 | worker 的环境加载链含分号及错误短路缺口，部分 cd/source 失败可能被后续命令掩盖；预检成功不等于所有 rank 使用相同环境 | 核对逐节点工作目录、解释器、前缀、镜像和载荷日志，不仅看 prepare PASS |
| platform/resource | 固定默认规则尚未形成完整站点策略入口；未强制期望卡数，CPU/内存/磁盘阈值不完整；可解析输出的内部命令失败可能漏报 | 核对采样原始退出码、实际卡数和站点需求；不能宣称完整系统健康策略均已覆盖 |
| N/A 与一致性 | N/A 条目仍可能被错误计入异常索引，缺失/超时节点可能没有完整一致性记录 | 同时比较参与节点、检查明细、原始采集和失败索引；不能以表格缺行认定一致 |
| RCCL 完整性 | 尺寸序列可能从首个观测值起验证，遗漏起始区间仍可能通过；实际 rank 校验未完整证明逐节点卡数与成员归属 | 人工核对期望尺寸、实际总卡数、各节点/rank 和正确性错误，不仅看 busbw 峰值 |
| 主动测试原有空闲预检 | 部分无法解析或 N/A 的数值存在被空闲脚本当作零的风险 | 先确认节点已分配且空闲；出现未知指标时查原始采样，不默认添加 skip-idle-check |
| RCCL/DeepEP 规模与设备选择 | 新 G/C 链路和逐节点 HIP 数量/PCI 复核尚待目标集群硬件验收；已有可见性限制可能导致设备不足或复核失败；空闲检查仍覆盖原有可见范围 | 验证四卡列表不被覆盖、不同节点列表、设备不足/无效及预检与执行一致；源码/计划不等于硬件通过，skip-idle-check 也不跳过设备复核 |
| DeepEP 能力与指标 | 单机当前仅允许 2/4/8 卡；完整多机每节点八卡、每组 2/4 节点，受 norm 断言与专家数整除限制；指标组合、dtype、rank 和重复记录覆盖不足，实际 GPU worker 总数证据不完整 | 核对全部模式与配置；不能以扩大 G/C、跳过 norm 或调整第三方矩阵宣称支持任意规模；计划 GPU worker 数不填入实际数量 |
| byte-flux 完整性 | case 重复、缺 start、重试及 sweep 失败的解析约束不完整，重试成功可能掩盖首次错误 | 核对全部 64 项及 sweep 终态、重试和原始退出码；不能只看解析后的 PASS |
| 超时与清理 | 当前到期见证并非严格的 timeout 事件证据；137 也可能来自 OOM/外部 KILL；清理总预算未覆盖全部排队和连接，部分保护路径环境加载失败可继续 | 保留既有超时问题待修；核对逐节点原始码、到期/清理记录和残留，不承诺严格总耗时或全部远端进程均已退出 |
| SSH 并发与错误输出 | 普通额度、保留清理通道及回退路径尚有边界缺陷；部分文件描述符重定向会丢失 stderr | 不把 N+2 作为已验证硬上限；缺错误日志时结合原始节点记录和 SSH 结果诊断 |
| 预检隔离 | 当前部分全局计划/基准损坏可能被当作单组故障隔离，健康组也可能没有完成所需预检 | 在实际运行前核对完整计划与全部基准；故障注入/混合场景需单独证据 |
| 容器重建与删除 | recreate 错把普通容器 ID 按 sha256: 格式校验，已有容器常被拒绝；delete/replace 的按名称删除有竞态；挂载检查不完整 | 不用于无人值守批量恢复；保留原容器和挂载证据，先完成专门整改及真实生命周期验收 |
| 容器身份与汇总 | 创建流程有身份文件回读，但 status 只核对状态/标签；SSH 重试不构成完整总时限；中间阶段 PASS 可能进入失败汇总，stopped 查询可 WARN 但整体 PASS/0 | 按实际路径核对 SSH 身份和节点最终阶段，不能仅依赖 summary 数字或退出 0 |
| 报告环境与日志路径 | report-only 只锁定部分报告身份，可能覆盖原 report-host 记录；公开组索引部分相对路径错误 | 重建前保留原记录，使用原报告环境；需要时从 .state 查原始证据 |
| 重跑计划 | 指纹未覆盖完整镜像/脚本/基准环境，计划成员/阶段与原事实校验不足；仅预检失败及混合失败阶段有缺口，当前需要登录节点 python3 | 先 dry-run，人工核对原组、卡数、阶段及环境；不自动缩组，不将重跑接口当作无人值守恢复保证 |
| 超大规模性能 | 已有部分集合索引、滚动调度和按需建目录；报告仍存在历史扫描与重复渲染，缺少完整大规模性能证据 | 按规模记录 SSH、控制器资源、报告延迟与清理耗时，不用源码优化替代实测结论 |
| 发布与第三方 | 当前测试矩阵包含旧断言；完整构建/安装与真实主动测试证据不齐，第三方 Gitlink、来源及版权/NOTICE 仍需收尾 | 不宣称全矩阵通过或已完成开源发布审核；发布前单独核对固定版本、许可、发行包和目标环境安装 |

## 证据判定

| 证据 | 可以证明 | 不能证明 |
|---|---|---|
| 静态源码与文档核对 | 文件、路由、参数和默认规则存在 | 命令在真实集群成功、性能达标或清理无残留 |
| `--dry-run` | 当前输入可形成计划，显示参与范围 | 目标环境可用、载荷启动、算子正确或性能达标 |
| 预检成功 | 已执行的依赖/身份/空闲检查结果 | 后续阶段、实际 MPI rank 与完整矩阵成功 |
| 因繁忙/缺依赖被阻断 | 拦截路径和相应证据存在 | 被阻断载荷已经测试通过 |
| 原始命令退出 0 | 对应进程成功退出 | 完整尺寸/模式覆盖，健康或性能一定合格 |
| 报告 PASS | 当前解析器在当前参与范围内给出 PASS | 已跳过节点、未覆盖组合或已知解析缺口均无问题 |
| 清理 CONFIRMED | 对应记录确认停止 | 所有未知进程或不同环境/namespace 中的进程均已检查 |

真实验收记录应包含版本与文件身份、可复现完整命令、原始退出码、参与/未参与节点、组与阶段、规则结果、原始日志和逐节点清理状态。明确区分源码核对、计划验证、阻断验证、真实载荷运行和未验证项；不得用替身程序的输出替代实际载荷证据。

## 文档与问题关闭

README 和指南描述可调用能力及当前限制，不表示当前版本达到完整生产验收标准。关闭问题需要对应代码差异与充分证据；文档整理、重建报告或更换描述均不能关闭未完成整改。既有冻结问题继续按原清单管理，不在本次文档整理中重新扩展或关闭。

## idle-check 的判定范围

显存和利用率按 Hy-smi 显示的百分比判断，二者均为零即空闲；百分比为零不代表硬件占用字节数绝对为零。Hy-smi 的 HCU Index/进程显存字段可能为空；此时仍通过其返回的宿主机 PID 与 Docker 进程成员关系确认节点级容器归属，不猜测卡号。非零指标但没有可定位 PID 时报告失败，不推测容器，也不重置设备。现有主动测试的阈值策略保持不变。
